# Prototype notes (Part 1.4 support)

Status: not started. The prototype itself lives in `/prototype/`; this file is the talking points required alongside it.

To answer:
1. **One thing chosen not to build, and why — answered:** automated supplier outreach (drafting/sending/tracking corrected-invoice requests). It would address the APAC analyst's specific complaint, but it's a supplier-communication workflow system, not a tax-determination system — a different build outside the brief's stated ask and the 2-engineer/8-week budget. See `answers/02-workflow-proposal.md`, point 7. The format-compliance *check* itself stays in scope; the outreach *workflow* doesn't.
2. One thing that surprised us while building it — **answered, from an actual live run, not a prediction:** retrieval-augmented context doesn't get filtered for relevance by default. On the first real run, the model cited an available knowledge-base entry (`KB-DE-002`, an intra-group cost-sharing exception) on a transaction that wasn't intra-group at all — it treated "present in context" as license to cite, without the reasoning explaining why it applied. That's a real, generalizable finding about building RAG-augmented systems: retrieval solves *availability*, not *relevance* — the model still needs to be explicitly required to justify why a retrieved entry applies to the specific facts in front of it. See `prototype/evals/eval-plan.md` section 3 for the full worked example, including a data-construction bug the same run surfaced (fixed, not used as a talking point, since "the model caught my own test-data error" isn't a finding about the model).
3. Which messy input the demo handles — **answered: not one, five, but with one flagship.** Duplicate-vendor-with-conflicting-tax-profiles (INV-1002) is the flagship, tied directly to the EMEA manager's unprompted complaint. Alongside it: a clean happy-path case (INV-1001), a format-compliance failure (INV-1003, Germany's *leistungsdatum* trap), an urgency-queue-jump case (INV-1004, Italy's tight window beating higher-confidence-but-less-urgent items), and a genuine tax-judgment ambiguity unrelated to data quality (INV-1005, needs a contract the invoice doesn't carry). See `prototype/data/invoices.json` and `prototype/README.md`'s build breakdown for the full set and which are must-build vs. should-build.
